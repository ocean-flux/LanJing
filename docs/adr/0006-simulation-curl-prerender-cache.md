# ADR 0006：仿真 3D 卷页采用空闲帧预渲染纹理缓存，否决按下时快照

- 状态：已采纳（立项以真机最小验证原型通过为前提）
- 日期：2026-09-02
- 影响范围：`src/features/turn/transition/CurlTransition.ts`、
  `TextPageSource.snapshotFor()` 实现、内存预算

## 背景

产品要求翻页模式至少包含单页仿真与双页仿真（见 ADR 0004，应用面做全做深）。
外部方案的「幽灵快照」思路——手指按下时把当前 DOM 页截成位图交给 WebGL 卷页——
方向对，**时序错**，且其骨架代码不可运行：`createImageBitmap` 的合法入参不含
`HTMLElement`，而 html2canvas / SVG foreignObject 类 DOM 快照在满屏中文页面上
是百毫秒级。把百毫秒级同步工作放在手势按下（约 3px 阈值）的关键路径上，
必然卡顿。

## 决定

1. 把 DOM 快照从手势关键路径移到**空闲帧**：页面稳定后（`requestIdleCallback` +
   等 `document.fonts.ready`）把相邻 2–3 页异步渲染为位图纹理并缓存。
2. 手指按下时命中缓存、0ms 进入 WebGL 卷页；抬起后切回 DOM，
   恢复文字选中与朗读能力。
3. 内存预算：单页纹理约 12MB/屏（CSS 像素 × 受限 DPR 上限 2），
   单页仿真缓存 3 屏约 36MB，双页仿真 4 屏约 48MB，超出即淘汰最远屏。
4. 纹理缓存失效条件：改排版参数、转屏、换外观包、字体就绪、分页重排。
5. 降级链：预渲染连续失败 / WebGL 上下文丢失 / 内存紧张 → CSS 2.5D；
   `prefers-reduced-motion` → 无动效（强制）。
6. 该转场立项前必须在低端真机完成最小验证原型（文本单页 / 文本双页 /
   图漫单页 / 图漫双页四组合），拿到帧时间与内存增量实测数据；
   未通过则只交付 CSS 2.5D。

## 依据

- 阅读场景中手指静止时间以秒计，空闲帧是自然存在的预算；关键路径上 0ms、
  空闲时 100ms+，是把不可行变成可行的唯一时序。
- `ImagePageSource.snapshotFor()` 直接返回 `ImageBitmap`（内容本来就是位图），
  不需要这条缓存管线——预渲染缓存的全部复杂度都在文本一侧（见 ADR 0005 的
  成本不对称结论）。
- 受限 DPR 与缓存上限把内存钉在可预期的区间，避免长会话显存膨胀。

## 后果

- `CurlTransition` 的可用性取决于纹理缓存命中率；缓存失效风暴（连续改排版）
  必须触发降级而不是阻塞翻页。
- 任何排版 / 外观变更路径都必须广播缓存失效，否则卷页会显示过期纹理。
- 性能声明以真机实测为准；外部方案的性能数字（120fps、65MB 等）无实测支撑，
  不得引用。

## 备选方案

- **按下时同步快照**（外部方案原案）：不可运行 + 关键路径百毫秒级，已否决。
- **不做仿真，只做 CSS 2.5D**：与产品定位冲突（用户明确要求单 / 双页仿真）；
  CSS 2.5D 保留为降级路径而非唯一形态。
- **服务端 / Rust 端光栅化页面**：本地-only 无服务端；Rust 光栅化 WebView DOM
  在技术上不存在可用路径，已否决。
