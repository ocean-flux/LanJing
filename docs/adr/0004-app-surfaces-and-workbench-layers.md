# ADR 0004：双层架构——工作台层与应用面层分离

- 状态：已采纳
- 日期：2026-09-02
- 影响范围：`src/features/apps/**`、`src/features/turn/**`（新增）、路由、后续所有应用面决策

## 背景

LanJing 长期被当作单层工作台来讨论：境场、来源与规则、资料库、设置共用一套
chrome 与 base-lyra 组件母版，整体气质克制、效率优先。在阅读器落地讨论中，
这一误判直接导致错误结论——「产品克制，所以翻页模式要少做、不做仿真动效」。

实际上 `src/features/apps/AppsHome.tsx` 早已声明五个按媒体类型划分的应用面
（reading / gallery / podcast / video / music，均 `enabled: false` 待实现）。
用户明确要求：「应用就是要做复杂的，和当前的工作台不一样，一旦进入一个应用
就可以沉浸式体验」。

## 决定

1. LanJing 是**双层架构**：工作台层（境场、来源、规则、资料库、设置）+
   应用面层（`/apps` 下的沉浸式体验面）。
2. 工作台层维持现状：base-lyra 母版、克制、效率优先。
3. 应用面层是另一套交互语言：进入后隐藏工作台 chrome（侧栏、工具栏），
   Esc / 返回手势退出；不受 base-lyra 的直角、`text-xs` 基线、32px 控件约束。
4. 应用面层的唯一共享约束：色值只能来自 `src/index.css` 的四个
   appearance pack，禁止在应用面里另存调色板。

## 依据

- 「克制」是工作台层的设计目标，不是全产品统一约束；把它套到沉浸式阅读 /
  看图体验上会系统性压低体验上限。
- 应用面按媒体类型分流（MediaKind → 应用面映射），每个面的交互范式天然不同
  （分页阅读 vs 连续看图 vs 播放），统一 chrome 反而是障碍。
- 色值单一来源的约束保留，是因为外观包切换必须对所有层同时生效；
  其余约束（密度、圆角、控件尺寸）恰好是应用面需要摆脱的。

## 后果

- 所有「这个功能该多复杂」的讨论必须先回答「它在哪一层」。
- 应用面功能（翻页模式数量、动效、排版自由度）按沉浸式标准设计，
  不再以工作台密度为参照。
- 新应用面落地时的固定动作：路由挂在 `/apps/<surface>/:resourceId`、
  实现沉浸式外壳（隐藏 chrome + 退出手势）、声明视觉语言边界。

## 备选方案

- **单层工作台，阅读器作为一个普通工作区**：已被用户否决；会把阅读体验压进
  工作台的密度与 chrome 里，与产品意图相反。
- **每个应用面完全独立设计系统**：会失去外观包统一切换的能力，维护成本不可控。
  色值单一来源是必须保留的底线。
